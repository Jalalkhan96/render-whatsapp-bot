# ABIX-AE Game Arcade + Ping Client-Safe Fix — 2026-10-05

## Game UX
- `-games`, `-arcade`, `-gamemenu` send clean normal image artwork first.
- A standard WhatsApp list is sent separately with real selectable game rows.
- Tapping a row produces a normal command such as `-dino` or `-dino jump`.
- Game state is kept in a bounded in-memory session map (256 sessions, 30-minute TTL).
- No fake-forward metadata, no native-flow relay, and no experimental rich HTML envelope are used by the default game path.
- Page navigation uses `-games 2` / previous-page rows.
- Core games have clickable controls: Dino, Flappy, Snake and RPS; the remaining arcade games have safe start/action controls.

## Why this change
The previous game sender attempted an experimental Rich HTML / native message envelope. Those message types are client-sensitive; Rich HTML is documented as Android-only/client-dependent, and the upstream Baileys v7 release line introduced richResponse/interactive-message support after rc9. A phone being fully updated does not guarantee that every experimental message envelope generated by an older/custom Baileys implementation will render.

## Ping
- Default `-ping` is text-only to avoid allocating a PNG buffer.
- Set `PING_IMAGE=true` only when the styled card is desired.
- Image mode remains single-flight and uses 72 DPI with cache disabled.
- Reaction remains opt-in with `PING_REACT=true`.
